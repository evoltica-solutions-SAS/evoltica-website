# docs/development/

> **Versión**: 1.0 · **Estado**: Active · **Última actualización**: 2026-07-07 · **Responsable**: Evoltica Solutions SAS

## Propósito

Espacio para notas técnicas de desarrollo que son más profundas o puntuales de lo que corresponde tener en [DEVELOPMENT_GUIDE.md](../../DEVELOPMENT_GUIDE.md) (que se mantiene como el conjunto de reglas vigentes y estables).

## Qué va aquí

- Postmortems técnicos de bugs no triviales (qué pasó, causa raíz, cómo se evitó a futuro).
- Notas de investigación técnica (p. ej. comparación de librerías antes de adoptar una).
- Guías de setup de entorno local más detalladas que lo que amerita el `README.md` principal del repo.
- Documentación de scripts o herramientas internas de desarrollo, si se agregan.

## Qué NO va aquí

- Convenciones vigentes de código/componentes/TypeScript → eso vive en [DEVELOPMENT_GUIDE.md](../../DEVELOPMENT_GUIDE.md).
- Decisiones de stack con alternativas evaluadas → eso es un ADR, ver [docs/decisions/](../decisions/).

## Convención de nombres

`AAAA-MM-DD-titulo-corto.md`, por ejemplo: `2026-10-01-postmortem-fallo-build-vercel.md`.

## Referencias
